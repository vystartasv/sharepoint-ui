## A component system shaped for SharePoint

SharePoint UI's focus is a tenant-aware task view that works in both a SharePoint page and an SPFx 1.24 Copilot UX component. The Copilot example reads and updates a real SharePoint list, inherits SharePoint theme tokens, and returns its visible state to the agent. React is optional; the sample uses custom elements directly.

```sh
npm install @spfx-fast/sharepoint-ui
```

The package targets SPFx 1.24 and React 18. React is an optional peer dependency; custom-element consumers can import only the definitions they need.

## Why use this for SharePoint?

Fluent UI is a strong general-purpose system. Choose SharePoint UI when you need low-payload, tenant-themed task surfaces that work without React in SPFx Copilot UX and SharePoint pages. The four-control custom-element slice measured 11,562 gzip bytes, 74% less than equivalent Fluent UI React 9.75 imports at 44,411 bytes. The metadata-driven field renderer measured 116,738 gzip bytes without React versus 129,343 with the React adapter; a common-fields form using lazy chunks measured 25,724 gzip bytes. The repository includes a real-list Copilot example and interactive preview. These are source-import payload measurements, not complete-app or render-speed claims. [See the benchmark and its limits](/sharepoint-ui/guides/payload/).

## Compose an SPFx view

```tsx
import { Button, SharePointUIProvider, ViewCard } from "@spfx-fast/sharepoint-ui/react";

export function RequestList({ items, locale, openItem }) {
  return (
    <SharePointUIProvider lang={locale}>
      {items.map(item => (
        <ViewCard key={item.Id} kind="list-item" title={item.Title} subtitle={item.Modified} description={item.Status}>
          <Button slot="action" appearance="primary" onClick={() => openItem(item.Id)}>Open item</Button>
        </ViewCard>
      ))}
    </SharePointUIProvider>
  );
}

// From the SPFx web part's render method, pass:
// locale={this.context.pageContext.cultureInfo.currentUICultureName}
```

The `lang` value controls localization and direction. Components inherit the site theme and stay within the SharePoint section that owns them. Keep SharePoint data access and persistence in the web part; the UI components expose the interaction and value changes.
