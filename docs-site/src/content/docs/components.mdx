# Component inventory

The library keeps one control per distinct task. Several old variants are consolidated: one `Button` covers actions; native `Input` types cover search, dates, files, colors, ranges, and numbers; semantic HTML covers common structure. The inventory has {inventory.components.length} components; {inventory.components.filter(component => component.available).length} are implemented in this branch.

## Use the components

```tsx
import { Button, Checkbox, Field, Input, SharePointThemeProvider } from "@spfx-fast/sharepoint-ui/react";
import "@spfx-fast/sharepoint-ui/styles.css";

<SharePointThemeProvider>
  <Field id="request-title" label="Request title" required hint="Use a short subject.">
    <Input name="title" required />
  </Field>
  <label><Checkbox name="notifyOwner" /> Notify the owner</label>
  <Button type="submit">Save request</Button>
</SharePointThemeProvider>
```

For list data, give the grid stable record keys and a readable row name:

```tsx
<DataGrid
  label="Open requests"
  caption="Open requests awaiting review"
  rows={requests}
  getRowId={row => row.id}
  rowLabel={row => row.title}
  selectable
  columns={[
    { key: "title", label: "Title" },
    { key: "owner", label: "Owner" },
    { key: "due", label: "Due" },
  ]}
/>
```

`PersonPicker` and `LookupPicker` accept results supplied by the host. They do not make SharePoint requests; load options with the web part's existing SPFx services, then persist changes in the host app.

For large fixed-height collections, use `VirtualList` with a stable key and a known row height. It only mounts the visible range plus overscan.

```tsx
<VirtualList
  label="Recent documents"
  items={documents}
  itemHeight={48}
  height={360}
  getItemKey={document => document.id}
  renderItem={document => <a href={document.url}>{document.name}</a>}
/>
```

## Additions for SharePoint work

`PersonPicker` and `LookupPicker` accept results supplied by the host. They do not call SharePoint. `DateRangePicker`, `Pagination`, `EmptyState`, `CopyButton`, and `CommandBar` fill common workbench tasks missing from the earlier set.

The React surface accepts standard native element props, including `aria-label`, `aria-labelledby`, `name`, `value`, `disabled`, `data-*`, `onChange`, and `onClick`. Each control remains a native HTML element or a small semantic composition.

To keep the inventory compact, `Input` also covers search, dates, files, colors, ranges, and numeric values through its native `type` prop. Those cases do not need separate components.

Menus use a native disclosure, and onboarding can be composed from `Dialog`, `Popover`, and `Tabs`. Rich-text editing remains the host app's responsibility because safe HTML storage requires a tenant-approved sanitizer; use `TextArea` for plain-text fields. Tooltips use the browser's native `title` attribute.
