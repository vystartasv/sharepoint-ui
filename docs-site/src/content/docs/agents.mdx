# Agent interaction guide

Use the page's accessibility tree as the interface contract. Native roles, visible labels, and normal browser events make components discoverable and operable without package-specific scripts.

## Find a control

Prefer role and accessible name. Use a stable `data-agent-id` only when the page contains duplicate names.

```ts
const title = page.getByRole("textbox", { name: "Work item title" });
await title.fill("Update the team site");
await page.getByRole("combobox", { name: "Status" }).selectOption("In progress");
await page.getByRole("checkbox", { name: "Notify the owner" }).check();
await page.getByRole("button", { name: "Save work item" }).click();
await expect(page.getByRole("status")).toContainText("Saved");
```

## Select by task

- Click or submit an action: `button` with a verb in its name.
- Enter text: `textbox` with a visible associated `label`.
- Choose one option: `combobox` or a labelled radio group.
- Toggle an independent option: `checkbox`; toggle an immediate preference: `switch`.
- Navigate: `link` with a destination in its name.
- Confirm a result: inspect the named `status` or `alert` region.

## State and errors

Read `checked`, `selected`, `expanded`, `disabled`, and `value` from the accessibility tree or native DOM. After an action, wait for the visible status or changed value. If validation fails, read the associated message and correct the field; do not infer success from a click alone.

## Stable selectors

Rendered UI controls forward standard `data-*` props. For duplicate labels, add a stable `data-agent-id` such as `save-work-item`; otherwise prefer role and label locators. Do not target generated classes, child positions, or visual coordinates when an accessible name exists.

See the plain Markdown copy at `/agents/AGENTS.md` for retrieval by coding agents.

## Resolve a component

Check the [component inventory](../components/) before choosing an element. The published package also exposes `@spfx-fast/sharepoint-ui/components.json` with one short summary per supported component. Choose by user task, then use that component's native role and label; avoid searching for old compound parts or appearance variants.

Examples:

- A labelled, validated value: `Field` with `Input` or `TextArea`.
- One fixed choice: `Select`; one-of-many: `RadioGroup` with `Radio`; multiple values: `TagPicker`.
- An immediate preference: `Switch`; a separately submitted choice: `Checkbox`.
- A record list: `DataGrid`; static columns: `Table`; a large fixed-height feed: `VirtualList`.
- A SharePoint person or lookup: `PersonPicker` or `LookupPicker`, with options loaded by the host.
- A searchable, paged result set: `ListView` with a labelled `FilterBar` and optional `ViewSwitcher`.
- File selection and upload status: `FileDropzone` and `AttachmentList`; the host performs the SharePoint upload.

Composite locator names stay explicit. A `FilterBar` named `Open requests filters` can contain a native searchbox named `Search requests`; its clear action is a button named `Clear filters`. `FileDropzone` exposes its native file input by its visible label. `ListView` names its results table `Open requests results` and its paging navigation `Open requests pages`. A `ViewSwitcher` is a group named `Open requests view` with buttons named after each view and an `aria-pressed` state.

```ts
await page.getByRole("search", { name: "Open requests filters" }).getByRole("searchbox", { name: "Search requests" }).fill("access");
await page.getByRole("button", { name: "Clear filters" }).click();
await expect(page.getByRole("status")).toContainText("3 requests shown");
await page.getByLabel("Supporting documents").setInputFiles("access-review.pdf");
await expect(page.getByRole("group", { name: "Supporting documents" }).getByRole("status")).toContainText("1 file selected");
await page.getByRole("button", { name: "Cards" }).click();
await expect(page.getByRole("button", { name: "Cards" })).toHaveAttribute("aria-pressed", "true");
```

The library does not fetch, save, or upload SharePoint data. Agents should use the host page's supported workflow for those operations, then verify the saved value in the page.
