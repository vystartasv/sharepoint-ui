`RichTextEditor` owns editing, formatting, link validation, and HTML sanitization. Your SPFx web part owns SharePoint access: provide a picker callback and save the emitted HTML through your existing list or page data service.

The toolbar includes paragraph, heading, quote, and preformatted block styles; bold, italic, underline, and strikethrough; clear formatting; lists; undo/redo; tables; links; and app-managed image uploads. Enhanced rich-text fields also expose font family, size, text color, and highlight color. The color controls include a quick palette with the active SharePoint accent plus a custom color picker. `SharePointUIProvider.strings` localizes these controls and their palette names (`richTextTextColor`, `richTextHighlightColor`, `richTextCustomColor`, `richTextThemeAccent`, and `colorSwatch`). Restricted SharePoint fields hide unsupported table, image, link, font, and color actions.

## Try the editor

Edit the note directly, or switch to **HTML source** to inspect and edit its value. Source changes pass through the editor's sanitizer and update the editable note; changes made in the editor update the source and the displayed sanitized value. ## Connect your picker

Adapt the picker already used by your web part. Return `null` when the user cancels. Otherwise return the destination URL and any display metadata; the editor fills its link form and waits for the user to select **Apply link**.

```tsx
import * as React from "react";
import {
  RichTextEditor,
  type RichTextEditorLinkPicker,
} from "@spfx-fast/sharepoint-ui/react";

const linkPicker: RichTextEditorLinkPicker = async current => {
  const selected = await openSharePointPageOrFilePicker({
    initialUrl: current?.href,
  });

  return selected
    ? { href: selected.url, text: selected.name, title: selected.name }
    : null;
};

function NotesEditor() {
  const [html, setHtml] = React.useState("");

  return (
    <RichTextEditor
      label="Notes"
      value={html}
      onValueChange={setHtml}
      linkPicker={linkPicker}
      onLinkPickerError={error => console.error("Link picker failed", error)}
    />
  );
}
```

`openSharePointPageOrFilePicker` represents the picker supplied by your host application; this package does not add a picker dependency or make tenant requests. The callback receives the current link when editing one. Its result must use an allowed `http:`, `https:`, or `mailto:` URL. Unsafe results are rejected, and picker failures are reported through `onLinkPickerError`.

## Save the value

Use the editor's sanitized `onValueChange` value with your normal SPFx persistence path. Provide loading, saved, and error feedback in the web part. Read back important writes where the workflow requires confirmation. To render saved content, pass it back through `RichTextEditor` or another sanitizer-aware renderer; do not inject it with raw `innerHTML`.

## Match the SharePoint field

When no mode or field is supplied, the editor uses sanitized `html` mode so an unconstrained host can retain the richest supported content. In React, pass SharePoint field metadata as `field`; the editor derives its mode and enabled actions on every render. The field is a capability ceiling: an explicit `contentMode` can choose a narrower mode, but cannot enable richer content than the destination permits; `allowHyperlink={false}` can further disable links, while `true` cannot override a field's explicit prohibition. For framework-neutral elements, use `getRichTextEditorFieldOptions(field)` to get the same field-derived options. Missing restrictions do not silently flatten content to text. The mapping is:

| SharePoint field settings | Editor mode | What users can save |
| --- | --- | --- |
| `RichText: false` | `plain` | Plain text only |
| `RichText: true`, `RestrictedMode: true` | `restricted` | Basic formatting; paste becomes plain text; no tables, images, or hyperlinks |
| `RichText: true`, `RestrictedMode: false`, `RichTextMode: "Compatible"` (or omitted) | `rich` | Rich formatting, tables, and images when an upload callback is supplied; links are available unless `AllowHyperlink` is explicitly false |
| `RichText: true`, `RestrictedMode: false`, `RichTextMode: "FullHtml"` | `html` | Broad safe semantic HTML, inline formatting, tables, and links unless `AllowHyperlink` is explicitly false |
| No relevant settings supplied | `html` | Maximum supported editing for an unconstrained host; output is still sanitized |

```tsx
import {
  RichTextEditor,
  type SharePointMultiLineField,
} from "@spfx-fast/sharepoint-ui/react";

// Load these settings with the field metadata your SPFx data layer already uses.
// The helper accepts SharePoint booleans as booleans or "TRUE"/"FALSE" strings.
const field: SharePointMultiLineField = {
  RichText: true,
  RestrictedMode: false,
  RichTextMode: "FullHtml",
  AllowHyperlink: true,
};

<RichTextEditor label="Project notes" field={field} />
```

The field accepts SharePoint's PascalCase metadata and camelCase equivalents. An explicit `AllowHyperlink: false` disables link creation and strips link wrappers in every rich mode; when the property is absent, safe links remain available. Plain mode emits plain text. Other modes emit sanitized HTML; `rich` preserves compatible formatting and `html` accepts additional semantic elements and safe text styles (such as color, font, and alignment) while still removing scripts, embedded objects, unsafe URLs, and unsupported attributes. Valid `lang` values and `dir="ltr|rtl|auto"` are preserved on supported elements, so multilingual content can keep its own language and reading direction inside a differently directed page. Set `contentMode="plain"`, `"restricted"`, or `"rich"` explicitly to narrow an unconstrained host or a field's available mode. Sanitization intentionally does not preserve arbitrary active HTML, scripts, embeds, or unsafe attributes. For custom elements, spread `getRichTextEditorFieldOptions(field)` onto `<spui-rich-text-editor>`.

This editor can format and serialize text color and highlight color in enhanced rich-text values. Microsoft Lists describes those formatting capabilities for enhanced rich-text columns, while its modern-form guide notes that some commands available in the classic editor (including table insertion and HTML source editing) are not in the modern SharePoint form. This library is not a pixel-for-pixel clone of either host editor: it provides its own controls, sanitizes output, and SharePoint may normalize saved HTML. See Microsoft's [enhanced rich-text column guide](https://support.microsoft.com/en-us/sharepoint/lists/data-and-lists/edit-a-rich-text-list-column) and [column options](https://support.microsoft.com/en-us/sharepoint/lists/data-and-lists/list-and-library-column-types-and-options).

## Load and save a SharePoint note field

Keep the field's `RichText`, `RestrictedMode`, `RichTextMode`, and `AllowHyperlink` metadata with your data layer and pass it as `field`. Use the field's **internal name** in REST requests; this example uses `Notes`. The SPFx `SPHttpClient` sends the current user's SharePoint authentication and uses the current web URL.

```tsx
import * as React from "react";
import { SPHttpClient } from "@microsoft/sp-http";
import type { WebPartContext } from "@microsoft/sp-webpart-base";
import { Button, RichTextEditor, type SharePointMultiLineField } from "@spfx-fast/sharepoint-ui/react";

type NoteItem = { Notes?: string | null };
type LoadedNote = { html: string; etag: string };

function noteUrl(context: WebPartContext, listId: string, itemId: number): string {
  return `${context.pageContext.web.absoluteUrl}/_api/web/lists(guid'${listId}')/items(${itemId})`;
}

async function loadNote(context: WebPartContext, listId: string, itemId: number): Promise<LoadedNote> {
  const response = await context.spHttpClient.get(
    `${noteUrl(context, listId, itemId)}?$select=Id,Notes`,
    SPHttpClient.configurations.v1,
    { headers: { accept: "application/json;odata.metadata=none" } },
  );
  if (!response.ok) throw new Error(`Could not load Notes (${response.status}).`);
  const item = await response.json() as NoteItem;
  return { html: item.Notes ?? "", etag: response.headers.get("ETag") ?? "*" };
}

async function saveNote(context: WebPartContext, listId: string, itemId: number, html: string, etag: string): Promise<void> {
  const response = await context.spHttpClient.post(noteUrl(context, listId, itemId), SPHttpClient.configurations.v1, {
    headers: {
      "content-type": "application/json;odata.metadata=none",
      "if-match": etag,
      "x-http-method": "MERGE",
    },
    body: JSON.stringify({ Notes: html }),
  });
  if (!response.ok) throw new Error(`Could not save Notes (${response.status}). Reload the item if another person changed it.`);
}

export function NotesEditor({ context, listId, itemId, field }: {
  context: WebPartContext;
  listId: string;
  itemId: number;
  field: SharePointMultiLineField;
}) {
  const [html, setHtml] = React.useState("");
  const [status, setStatus] = React.useState("Loading note…");
  const [ready, setReady] = React.useState(false);
  const [saving, setSaving] = React.useState(false);
  const etag = React.useRef("*");

  React.useEffect(() => {
    let active = true;
    void loadNote(context, listId, itemId).then(item => {
      if (!active) return;
      etag.current = item.etag;
      setHtml(item.html);
      setReady(true);
      setStatus("");
    }).catch(error => { if (active) setStatus(String(error)); });
    return () => { active = false; };
  }, [context, listId, itemId]);

  const save = async () => {
    setSaving(true);
    setStatus("Saving…");
    try {
      await saveNote(context, listId, itemId, html, etag.current);
      const saved = await loadNote(context, listId, itemId);
      etag.current = saved.etag;
      setHtml(saved.html);
      setStatus("Saved");
    } catch (error) {
      setStatus(error instanceof Error ? error.message : "Could not save the note.");
    } finally {
      setSaving(false);
    }
  };

  return <>
    <RichTextEditor label="Notes" value={html} onValueChange={setHtml} field={field} disabled={!ready || saving} />
    <Button appearance="primary" onClick={() => void save()} disabled={!ready || saving}>Save notes</Button>
    <span role="status" aria-live="polite">{status}</span>
  </>;
}
```

`Notes` must be the field's internal name, `listId` must be the list GUID, and the caller should supply the field metadata read from that list. A stale ETag is reported as a save error instead of silently replacing another user's edit. The sample reads the saved value back so the next update uses the current ETag and reflects the server value. For more complex list queries and writes, Microsoft recommends a typed SharePoint data library such as PnPjs over hand-built REST calls. See Microsoft's guides for [SPHttpClient in SPFx](https://learn.microsoft.com/en-us/sharepoint/dev/spfx/connect-to-sharepoint) and [list item REST operations](https://learn.microsoft.com/en-us/sharepoint/dev/sp-add-ins/working-with-lists-and-list-items-with-rest).

## Load the editor only when needed

For pages where editing is optional, keep the editor out of the initial web-part bundle. `React.lazy` lets the SPFx webpack build place the React adapter and editor in an async chunk, requested when the user starts editing.

```tsx
import * as React from "react";

const LazyRichTextEditor = React.lazy(() =>
  import("@spfx-fast/sharepoint-ui/react").then(({ RichTextEditor }) => ({
    default: RichTextEditor,
  })),
);

function DeferredNotesEditor({ value, onChange }: {
  value: string;
  onChange: (html: string) => void;
}) {
  const [editing, setEditing] = React.useState(false);

  if (!editing) {
    return <button type="button" onClick={() => setEditing(true)}>Edit notes</button>;
  }

  return (
    <React.Suspense fallback={<div role="status">Loading editor…</div>}>
      <LazyRichTextEditor label="Notes" value={value} onValueChange={onChange} />
    </React.Suspense>
  );
}
```

Keep the editor imported only through this lazy boundary if you want it excluded from the initial bundle. If the page always opens in edit mode, render it directly instead of adding a loading step.
