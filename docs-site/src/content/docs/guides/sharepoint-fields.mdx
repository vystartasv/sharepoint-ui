---
title: SharePoint field adapters
description: Turn SharePoint list field metadata into a predictable, typed control recipe without importing control implementations.
---

`getSharePointFieldAdapter()` maps a SharePoint REST or CSOM field definition to a small control recipe. It has no SPFx or React dependency, so a data layer can choose the UI without loading the library's components.

```ts
import { getSharePointFieldAdapter } from "@spfx-fast/sharepoint-ui/sharepoint-fields";

const adapter = getSharePointFieldAdapter(field);
// adapter.control, adapter.label, adapter.name, adapter.required, adapter.readOnly
```

## Mappings

| SharePoint field | Recipe | Notes |
| --- | --- | --- |
| Text | `input`, type `text` | Uses the display name, internal name, description, and required flag; includes `maxLength` when provided. |
| Integer, Number, Currency | `input`, type `number` | Includes numeric `min`/`max`; integer uses step `1`, decimal fields use configured precision or `any`. |
| URL | `input`, type `url` | `urlFormat` preserves SharePoint's hyperlink or picture display setting for record views. |
| Note without rich text | `textarea` | SharePoint's plain-text field stays plain text. |
| Note with rich text | `rich-text-editor` | Includes the existing `richText` options; explicit SharePoint restrictions win. |
| Choice | `select` or `radio-group` | Reads `Choices` and `EditFormat` in the order SharePoint provides. |
| MultiChoice | `multi-choice` | Includes the choices and fill-in setting; render as a checkbox list. |
| Boolean | `checkbox` | Uses the library Checkbox. |
| DateTime | `date-picker` or `input` | Date-only fields use `date-picker`; fields with time enabled use `input` with `inputType: "datetime-local"` so hours and minutes are editable. |
| Lookup, User | `combobox` | `multiple` follows field metadata. Lookup fields can expose `lookupSource` when SharePoint supplied its source-list metadata. |
| Managed metadata (`TaxonomyFieldType`, `TaxonomyFieldTypeMulti`) | `taxonomy` | Single terms use `ComboBox`; multi-term fields use `TagPicker`. The adapter exposes `termSetId`; the host supplies authorized, localized term options. |
| Geolocation | `geolocation` | Uses latitude and longitude controls; values normalize to `{ latitude, longitude }` and serialize as `SP.FieldGeolocationValue`. |
| Counter, Computed, Calculated | `read-only` | SharePoint calculates or manages these values. |
| Other types | `unsupported` | Includes the source `fieldType` and a reason; use a specialized renderer. |

Both SharePoint's PascalCase fields (`TypeAsString`, `InternalName`) and camelCase equivalents are accepted. `FieldTypeKind` numeric values are supported when `TypeAsString` is absent. Hidden, required, read-only, text-length, numeric-bound, description, choice, and multi-value metadata are retained on the recipe.

## Load the list's field definitions

Use the list GUID and its web URL to request field metadata, including type-specific properties such as choices and lookup sources. The URL is bounded and requests the available field properties so the adapter has enough information to select the right control:

```ts
import { SPHttpClient } from "@microsoft/sp-http";
import {
  getSharePointFieldAdapter,
  getSharePointFieldMetadataUrl,
  getSharePointNextPageUrl,
  type SharePointFieldMetadata
} from "@spfx-fast/sharepoint-ui/sharepoint-fields";

const webUrl = context.pageContext.web.absoluteUrl;
const response = await context.spHttpClient.get(
  getSharePointFieldMetadataUrl(webUrl, listId),
  SPHttpClient.configurations.v1,
  { headers: { Accept: "application/json;odata=nometadata" } }
);
if (!response.ok) throw new Error(`Field request failed: ${response.status}`);
const page = await response.json() as {
  value?: SharePointFieldMetadata[];
  "@odata.nextLink"?: string;
};
const adapters = (page.value ?? []).map(getSharePointFieldAdapter).filter(field => !field.hidden);
const nextPageUrl = getSharePointNextPageUrl(webUrl, page["@odata.nextLink"]);
```

If `nextPageUrl` is non-null, request it and append the next page's adapters. Hide columns from the form using `hidden`; disable `readOnly` fields, and use `control` to select the matching library component. SharePoint exposes field definitions through its list `Fields` endpoint; `$select=*` returns the available field properties. See Microsoft's [SharePoint OData query guidance](https://learn.microsoft.com/en-us/sharepoint/dev/sp-add-ins/use-odata-query-operations-in-sharepoint-rest-requests).

## Load and save lookup selections

SharePoint identifies lookup values by the source list's item ID. The field metadata supplies its `LookupList` and `LookupField`; pass the source list's web URL to create a bounded options request:

```ts
import { SPHttpClient } from "@microsoft/sp-http";
import { getSharePointFieldAdapter, getSharePointLookupOptionsUrl, getSharePointNextPageUrl } from "@spfx-fast/sharepoint-ui/sharepoint-fields";

const adapter = getSharePointFieldAdapter(column);
const source = adapter.lookupSource;
if (!source) throw new Error("SharePoint did not provide a lookup source for this field.");
const optionsUrl = getSharePointLookupOptionsUrl(column, lookupWebUrl, 100);
const response = await context.spHttpClient.get(optionsUrl, SPHttpClient.configurations.v1);
if (!response.ok) throw new Error(`Lookup request failed: ${response.status}`);
const result = await response.json() as {
  value?: Array<Record<string, unknown> & { Id: number }>;
  "@odata.nextLink"?: string;
  "odata.nextLink"?: string;
  d?: { results?: Array<Record<string, unknown> & { Id: number }>; __next?: string };
};
const items = result.value ?? result.d?.results ?? [];
const options = items.map(item => ({
  value: String(item.Id),
  label: String(item[source.displayField] ?? "")
}));
const nextPageUrl = getSharePointNextPageUrl(lookupWebUrl, result["@odata.nextLink"] ?? result["odata.nextLink"] ?? result.d?.__next);
```

Use `options` as the values for the library's `ComboBox`. If `nextPageUrl` is non-null, request it and repeat; the helper accepts absolute or relative OData links and rejects a different origin before the host sends credentials. The URL requests only `Id` and the configured display field. For a cross-web lookup, pass the source web URL, which can differ from the current list's web.

Use the IDs returned by the options or people picker to create an item update body. The helper handles single/multiple fields and clearing a selection:

```ts
import { serializeSharePointLookupValue } from "@spfx-fast/sharepoint-ui/sharepoint-fields";

const patch = serializeSharePointLookupValue(column, selectedIds);
// Single: { ProjectId: 42 }
// Multi:  { ReviewersId: { results: [17, 21] } }
await saveItem({ ...otherChanges, ...patch });
```

The focused lookup serializer also blocks writes to read-only fields and rejects empty selections for required fields. Pass `null` or an empty array only to clear an optional field.

Pass numeric IDs or digit strings; malformed and non-positive IDs throw instead of becoming a display-name write. For people fields, this serializes selected user/group IDs but does not search the tenant directory. Use an SPFx people-picker service appropriate to your tenant and permissions; a site's existing users are not a substitute for directory search. SharePoint REST requires lookup values to be selected/expanded explicitly and returns related values through `$select`/`$expand`; see Microsoft's [OData query guidance](https://learn.microsoft.com/en-us/sharepoint/dev/sp-add-ins/use-odata-query-operations-in-sharepoint-rest-requests) and the [`LookupList`](https://learn.microsoft.com/en-us/dotnet/api/microsoft.sharepoint.client.fieldlookup.lookuplist?view=sharepoint-csom) / [`LookupField`](https://learn.microsoft.com/en-us/dotnet/api/microsoft.sharepoint.client.fieldlookup.lookupfield?view=sharepoint-csom) metadata.

## Render and save managed metadata

Managed-metadata fields need terms from the field's term set. The library maps them to a single-value `ComboBox` or multi-value `TagPicker`; the host loads terms with its approved SharePoint/Graph authentication and passes options as `{ value: termGuid, label, wssId? }`. Use the label for the user's current locale and keep the stable term GUID as the value. Microsoft Graph returns a set's first-level terms from `/sites/{site-id}/termStore/sets/{set-id}/children`; request child terms recursively if the taxonomy is hierarchical. Delegated access requires `TermStore.Read.All`. The adapter returns `termSetId` when SharePoint includes `TermSetId` in the field metadata. See Microsoft's [list children API](https://learn.microsoft.com/en-us/graph/api/termstore-term-list-children?view=graph-rest-1.0).

SharePoint REST item reads expose a taxonomy term as `{ Label, TermGuid, WssId }`; depending on the endpoint, multi-values can arrive as a collection or as the `WssId;#Label|TermGuid` form string. Normalize the read value before giving it to the component:

```ts
import { normalizeSharePointTaxonomyValue } from "@spfx-fast/sharepoint-ui/sharepoint-fields";

const initialTerms = normalizeSharePointTaxonomyValue(field, item[field.InternalName]);
```

The normalized value is `{ label, termGuid, wssId? }` for one term or an array for a multi-term field. `wssId` can be omitted when the host does not know it; serialization uses `-1` so SharePoint can resolve the term. Use the dedicated serializer with `ValidateUpdateListItem`, because taxonomy values use SharePoint's form-value format rather than the ordinary list-item PATCH shape:

```tsx
import { useState } from "react";
import { SharePointField } from "@spfx-fast/sharepoint-ui/react";
import type { SharePointTaxonomyTermValue } from "@spfx-fast/sharepoint-ui/sharepoint-fields";

const [selected, setSelected] = useState<SharePointTaxonomyTermValue | null>({
  label: "Operations",
  termGuid: "55c05dc1-7ec3-4c4b-8c9e-0b4a6bbd19a6",
});

<SharePointField field={field} options={termOptions} value={selected} onValueChange={setSelected} />
```

```ts
import {
  getSharePointValidateUpdateListItemUrl,
  serializeSharePointTaxonomyFieldFormValue,
} from "@spfx-fast/sharepoint-ui/sharepoint-fields";

const formValue = serializeSharePointTaxonomyFieldFormValue(field, selected);
const url = getSharePointValidateUpdateListItemUrl(webUrl, listId, itemId);
const response = await context.spHttpClient.post(url, SPHttpClient.configurations.v1, {
  headers: { Accept: "application/json;odata=nometadata", "Content-Type": "application/json;odata=nometadata" },
  body: JSON.stringify({ formValues: [formValue], bNewDocumentUpdate: false }),
});
if (!response.ok) throw new Error(`SharePoint update failed: ${response.status}`);
const payload = await response.json() as { value?: Array<{ FieldName: string; HasException: boolean; ErrorMessage?: string }> };
const results = payload.value ?? [];
const failure = results.find(result => result.HasException || result.ErrorMessage);
if (failure) throw new Error(failure.ErrorMessage || `SharePoint rejected ${failure.FieldName}.`);
```

For multi-term fields, pass an array of term values. Pass `null` or `[]` to clear an optional field; required fields reject empty values. Microsoft's [`TaxonomyFieldValue` shape](https://learn.microsoft.com/en-us/dotnet/api/microsoft.sharepoint.client.taxonomy.taxonomyfieldvalue?view=sharepoint-csom) exposes label, term GUID, and WssId. The form serialization follows the [taxonomy value format](https://learn.microsoft.com/en-us/openspecs/sharepoint_protocols/ms-emmcsom/489ac564-28b1-41bb-9701-c01611e5156e) and the [`ValidateUpdateListItem` operation](https://learn.microsoft.com/en-us/openspecs/sharepoint_protocols/ms-csomspt/652ab52f-8f47-4eec-95fd-743af5ee38cc). The library does not silently use a label-only write or retrieve terms without the host's authorization.

## Save choice values

`serializeSharePointChoiceValue()` validates values against the field's configured choices unless `FillInChoice` is enabled. A single Choice is serialized as a string; MultiChoice uses SharePoint's `results` array shape:

```ts
import { serializeSharePointChoiceValue } from "@spfx-fast/sharepoint-ui/sharepoint-fields";

serializeSharePointChoiceValue(statusField, "Approved");
// { Status: "Approved" }
serializeSharePointChoiceValue(categoryField, ["Finance", "Operations"]);
// { Categories: { results: ["Finance", "Operations"] } }
```

Pass `null` to clear an optional Choice or MultiChoice field. Required fields reject empty values, and read-only fields reject writes. Unknown values throw when the field disallows fill-in choices; duplicate multi-values are removed while preserving their order.

## Serialize the other common field types

Use `serializeSharePointFieldValue()` for text, Note, Boolean, integer, number, currency, date/time, URL, Choice, MultiChoice, lookup, and person values. It routes the specialized choice and ID fields through the same validation as their focused helpers:

```ts
import { serializeSharePointFieldValue } from "@spfx-fast/sharepoint-ui/sharepoint-fields";

serializeSharePointFieldValue(titleField, "Quarterly access review"); // { Title: "Quarterly access review" }
serializeSharePointFieldValue(approvedField, true);                    // { Approved: true }
serializeSharePointFieldValue(amountField, "125.50");                  // { Amount: 125.5 }
serializeSharePointFieldValue(dueDateField, new Date());               // ISO date string
serializeSharePointFieldValue(linkField, { url: "/sites/ops/guide", description: "Open guide" });
serializeSharePointFieldValue(locationField, { latitude: 51.5072, longitude: -0.1276 });
// { Location: { __metadata: { type: "SP.FieldGeolocationValue" }, Latitude: 51.5072, Longitude: -0.1276 } }
```

The helper rejects text values over SharePoint's `MaxLength` and numeric values outside `MinimumValue`/`MaximumValue` (or `Min`/`Max`) when those bounds are present.

Use `null` to clear nullable values. Read-only fields and empty values for required fields are rejected; `false` and `0` are valid values. Numeric strings are parsed as whole values; non-finite numbers and unsafe integers are rejected, and configured `Decimals` precision is enforced (trailing zeroes do not count as extra precision). URL fields accept absolute HTTP(S) or server-relative URLs and serialize to SharePoint's [`SP.FieldUrlValue`](https://learn.microsoft.com/en-us/dotnet/api/microsoft.sharepoint.client.fieldurlvalue?view=sharepoint-csom) shape. Geolocation accepts decimal degrees in `{ latitude, longitude }` order or a SharePoint coordinate object; WKT `POINT` input is normalized from longitude/latitude order. Latitude and longitude bounds are validated before serialization. Date-only ISO strings are preserved, date-time strings with a timezone keep that offset, and local date-time strings or `Date` objects become ISO UTC strings. The helper does not send the request or replace SharePoint-side validation.

## Serialize one form patch

Pass the field metadata and current values keyed by SharePoint `InternalName` to `serializeSharePointFieldValues()`:

```ts
import { getSharePointListItemUrl, serializeSharePointFieldValues } from "@spfx-fast/sharepoint-ui/sharepoint-fields";

const patch = serializeSharePointFieldValues(fields, {
  Title: "Quarterly access review",
  Approved: true,
  Summary: null // explicitly clear this optional field
});
const itemUrl = getSharePointListItemUrl(webUrl, listId, itemId);
await saveItem(itemUrl, patch);
```

Only supplied values are included, so omitted fields remain untouched in a PATCH. Explicit `null` clears a nullable value; empty required values, read-only writes, unknown field names, property collisions, and invalid bounds throw before the request. Missing required fields are allowed in partial edits; new-item forms should include every required value. `getSharePointListItemUrl()` validates the list GUID and positive item ID. The host still sends the authorized request and supplies the list item's entity type and ETag as required by its REST update strategy; see Microsoft's [list-item REST guidance](https://learn.microsoft.com/en-us/sharepoint/dev/sp-add-ins/working-with-lists-and-list-items-with-rest#update-list-item).

## Render a metadata-driven form

[`SharePointField`](/sharepoint-ui/components/sharepoint-fields/sharepoint-field/) chooses the matching library control, applies the field label and description, and maps changes to one value shape. It handles text, numeric, URL, geolocation, plain and rich Note, Choice, MultiChoice, Boolean, DateTime, Lookup, User, and managed-metadata fields. Geolocation values are `{ latitude, longitude }`; React defaults come from `SharePointUIProvider` strings `geolocationLatitude` and `geolocationLongitude`, with `latitudeLabel` and `longitudeLabel` props for per-field overrides. Framework-neutral `<spui-sharepoint-field>` users can localize the labels with `latitude-label` and `longitude-label` attributes. Both paths use the same SharePoint metadata adapter. For taxonomy fields, load localized options from the term set and save with `serializeSharePointTaxonomyFieldFormValue()` as described above. The form can stay driven by SharePoint metadata:

```tsx
import { useState } from "react";
import { SharePointField, type SharePointFieldValue } from "@spfx-fast/sharepoint-ui/react";
import type { SharePointFieldMetadata } from "@spfx-fast/sharepoint-ui/sharepoint-fields";

function DynamicListForm({
  fields,
  optionsByField
}: {
  fields: SharePointFieldMetadata[];
  optionsByField: Record<string, { value: string | number; label: string }[]>;
}) {
  const [values, setValues] = useState<Record<string, SharePointFieldValue>>({});

  return <form>{fields.map(field => {
    const name = field.InternalName ?? field.internalName ?? "";
    return <SharePointField
      key={name}
      field={field}
      value={values[name]}
      options={optionsByField[name]}
      onValueChange={value => setValues(current => ({ ...current, [name]: value }))}
    />;
  })}</form>;
}
```

The `options` prop is for Lookup and User fields: the host loads those choices with its authorized SharePoint or people-search service. Choice and MultiChoice options come from the field metadata. `defaultValue` enables local uncontrolled use; pass `value` and `onValueChange` to control the field from form state. Localize the `emptyOptionLabel` and `addChoiceLabel` prompts for the current language. Unsupported SharePoint field types stay explicit; supply `renderUnsupported` for a specialized control.

| Property | Purpose |
| --- | --- |
| `field` | SharePoint field metadata used to choose the control and its rules. |
| `value` / `defaultValue` | Current value for controlled use, or initial value for local use. |
| `onValueChange` | Receives the value in the shape expected by the field serializer. |
| `options` | Loaded choices for Lookup and User fields. |
| `disabled`, `hint`, `validationMessage` | Apply form state and help text consistently. |
| `renderUnsupported` | Render a custom control for an unsupported field type. |
| `emptyOptionLabel`, `addChoiceLabel` | Localize the empty and fill-in choice prompts. |
| `id`, `className`, `style`, `data-*`, ARIA attributes | Target and style the field wrapper like other React components. |

For plain JavaScript, Copilot UX, or another framework, register the custom element and assign metadata and options as properties:

```ts
import { defineSharePointField } from "@spfx-fast/sharepoint-ui/elements/sharepoint-fields";

defineSharePointField();
const field = document.querySelector("spui-sharepoint-field")!;
field.field = column;
field.value = item[column.InternalName];
field.options = lookupOptions; // Lookup and User values loaded by the host
field.addEventListener("spui-field-value-change", event => {
  const { field: changedField, value } = event.detail;
  draft[changedField.InternalName] = value;
});
```

`field` and `options` are JavaScript properties because they contain objects. The element dispatches a bubbling, composed `spui-field-value-change` event and never fetches or saves SharePoint data itself.

## Customize a single control

Use the adapter directly when a form needs a custom layout or specialized control. A choice field can be rendered as a Select:

```tsx
import { Select } from "@spfx-fast/sharepoint-ui/react";
import { getSharePointFieldAdapter } from "@spfx-fast/sharepoint-ui/sharepoint-fields";

const field = getSharePointFieldAdapter(column);

if (field.hidden || field.control !== "select") return null;

return (
  <Select label={field.label} name={field.name} required={field.required} disabled={field.readOnly}>
    {field.choices?.map(choice => <option key={choice} value={choice}>{choice}</option>)}
  </Select>
);
```

For a SharePoint Note field, pass the original field metadata to `RichTextEditor`; it uses the same rules as `getRichTextEditorFieldOptions()`:

```tsx
import { RichTextEditor } from "@spfx-fast/sharepoint-ui/react";

<RichTextEditor label={field.label} name={field.name} required={field.required} field={column} />
```

The adapter describes the editor and provides helpers for lookup option URLs and field-value payloads. Your app still owns authorized fetching, people search, permissions, persistence, and handling SharePoint's response. Unknown field types remain explicit instead of being coerced to text.
