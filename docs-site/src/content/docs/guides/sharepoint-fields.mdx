---
title: SharePoint field adapters
description: Turn SharePoint list field metadata into a predictable, typed control recipe without importing control implementations.
---

`getSharePointFieldAdapter()` maps a SharePoint REST or CSOM field definition to a small control recipe. It has no SPFx or React dependency, so a data layer can choose the UI without loading the library's components.

```ts
import { getSharePointFieldAdapter } from "@spfx-fast/sharepoint-ui/sharepoint-fields";

const adapter = getSharePointFieldAdapter(field);
// adapter.control, adapter.label, adapter.name, adapter.required, adapter.readOnly
```

## Mappings

| SharePoint field | Recipe | Notes |
| --- | --- | --- |
| Text | `input`, type `text` | Uses the display name, internal name, description, and required flag; includes `maxLength` when provided. |
| Integer, Number, Currency | `input`, type `number` | Includes numeric `min`/`max`; integer uses step `1`, decimal fields use configured precision or `any`. |
| URL | `input`, type `url` | `urlFormat` preserves SharePoint's hyperlink or picture display setting for record views. |
| Note without rich text | `textarea` | SharePoint's plain-text field stays plain text. |
| Note with rich text | `rich-text-editor` | Includes the existing `richText` options; explicit SharePoint restrictions win. |
| Choice | `select` or `radio-group` | Reads `Choices` and `EditFormat` in the order SharePoint provides. |
| MultiChoice | `multi-choice` | Includes the choices and fill-in setting; render as a checkbox list. |
| Boolean | `checkbox` | Uses the library Checkbox. |
| DateTime | `date-picker` or `input` | Date-only fields use `date-picker`; fields with time enabled use `input` with `inputType: "datetime-local"` so hours and minutes are editable. |
| Lookup, User | `combobox` | `multiple` follows field metadata. Lookup fields can expose `lookupSource` when SharePoint supplied its source-list metadata. |
| Counter, Computed, Calculated | `read-only` | SharePoint calculates or manages these values. |
| Other types | `unsupported` | Includes the source `fieldType` and a reason; use a specialized renderer. |

Both SharePoint's PascalCase fields (`TypeAsString`, `InternalName`) and camelCase equivalents are accepted. `FieldTypeKind` numeric values are supported when `TypeAsString` is absent. Hidden, required, read-only, text-length, numeric-bound, description, choice, and multi-value metadata are retained on the recipe.

## Load the list's field definitions

Use the list GUID and its web URL to request field metadata, including type-specific properties such as choices and lookup sources. The URL is bounded and requests the available field properties so the adapter has enough information to select the right control:

```ts
import { SPHttpClient } from "@microsoft/sp-http";
import {
  getSharePointFieldAdapter,
  getSharePointFieldMetadataUrl,
  getSharePointNextPageUrl,
  type SharePointFieldMetadata
} from "@spfx-fast/sharepoint-ui/sharepoint-fields";

const webUrl = context.pageContext.web.absoluteUrl;
const response = await context.spHttpClient.get(
  getSharePointFieldMetadataUrl(webUrl, listId),
  SPHttpClient.configurations.v1,
  { headers: { Accept: "application/json;odata=nometadata" } }
);
if (!response.ok) throw new Error(`Field request failed: ${response.status}`);
const page = await response.json() as {
  value?: SharePointFieldMetadata[];
  "@odata.nextLink"?: string;
};
const adapters = (page.value ?? []).map(getSharePointFieldAdapter).filter(field => !field.hidden);
const nextPageUrl = getSharePointNextPageUrl(webUrl, page["@odata.nextLink"]);
```

If `nextPageUrl` is non-null, request it and append the next page's adapters. Hide columns from the form using `hidden`; disable `readOnly` fields, and use `control` to select the matching library component. SharePoint exposes field definitions through its list `Fields` endpoint; `$select=*` returns the available field properties. See Microsoft's [SharePoint OData query guidance](https://learn.microsoft.com/en-us/sharepoint/dev/sp-add-ins/use-odata-query-operations-in-sharepoint-rest-requests).

## Load and save lookup selections

SharePoint identifies lookup values by the source list's item ID. The field metadata supplies its `LookupList` and `LookupField`; pass the source list's web URL to create a bounded options request:

```ts
import { SPHttpClient } from "@microsoft/sp-http";
import { getSharePointFieldAdapter, getSharePointLookupOptionsUrl, getSharePointNextPageUrl } from "@spfx-fast/sharepoint-ui/sharepoint-fields";

const adapter = getSharePointFieldAdapter(column);
const source = adapter.lookupSource;
if (!source) throw new Error("SharePoint did not provide a lookup source for this field.");
const optionsUrl = getSharePointLookupOptionsUrl(column, lookupWebUrl, 100);
const response = await context.spHttpClient.get(optionsUrl, SPHttpClient.configurations.v1);
if (!response.ok) throw new Error(`Lookup request failed: ${response.status}`);
const result = await response.json() as {
  value?: Array<Record<string, unknown> & { Id: number }>;
  "@odata.nextLink"?: string;
  "odata.nextLink"?: string;
  d?: { results?: Array<Record<string, unknown> & { Id: number }>; __next?: string };
};
const items = result.value ?? result.d?.results ?? [];
const options = items.map(item => ({
  value: String(item.Id),
  label: String(item[source.displayField] ?? "")
}));
const nextPageUrl = getSharePointNextPageUrl(lookupWebUrl, result["@odata.nextLink"] ?? result["odata.nextLink"] ?? result.d?.__next);
```

Use `options` as the values for the library's `ComboBox`. If `nextPageUrl` is non-null, request it and repeat; the helper accepts absolute or relative OData links and rejects a different origin before the host sends credentials. The URL requests only `Id` and the configured display field. For a cross-web lookup, pass the source web URL, which can differ from the current list's web.

Use the IDs returned by the options or people picker to create an item update body. The helper handles single/multiple fields and clearing a selection:

```ts
import { serializeSharePointLookupValue } from "@spfx-fast/sharepoint-ui/sharepoint-fields";

const patch = serializeSharePointLookupValue(column, selectedIds);
// Single: { ProjectId: 42 }
// Multi:  { ReviewersId: { results: [17, 21] } }
await saveItem({ ...otherChanges, ...patch });
```

The focused lookup serializer also blocks writes to read-only fields and rejects empty selections for required fields. Pass `null` or an empty array only to clear an optional field.

Pass numeric IDs or digit strings; malformed and non-positive IDs throw instead of becoming a display-name write. For people fields, this serializes selected user/group IDs but does not search the tenant directory. Use an SPFx people-picker service appropriate to your tenant and permissions; a site's existing users are not a substitute for directory search. SharePoint REST requires lookup values to be selected/expanded explicitly and returns related values through `$select`/`$expand`; see Microsoft's [OData query guidance](https://learn.microsoft.com/en-us/sharepoint/dev/sp-add-ins/use-odata-query-operations-in-sharepoint-rest-requests) and the [`LookupList`](https://learn.microsoft.com/en-us/dotnet/api/microsoft.sharepoint.client.fieldlookup.lookuplist?view=sharepoint-csom) / [`LookupField`](https://learn.microsoft.com/en-us/dotnet/api/microsoft.sharepoint.client.fieldlookup.lookupfield?view=sharepoint-csom) metadata.

## Save choice values

`serializeSharePointChoiceValue()` validates values against the field's configured choices unless `FillInChoice` is enabled. A single Choice is serialized as a string; MultiChoice uses SharePoint's `results` array shape:

```ts
import { serializeSharePointChoiceValue } from "@spfx-fast/sharepoint-ui/sharepoint-fields";

serializeSharePointChoiceValue(statusField, "Approved");
// { Status: "Approved" }
serializeSharePointChoiceValue(categoryField, ["Finance", "Operations"]);
// { Categories: { results: ["Finance", "Operations"] } }
```

Pass `null` to clear an optional Choice or MultiChoice field. Required fields reject empty values, and read-only fields reject writes. Unknown values throw when the field disallows fill-in choices; duplicate multi-values are removed while preserving their order.

## Serialize the other common field types

Use `serializeSharePointFieldValue()` for text, Note, Boolean, integer, number, currency, date/time, URL, Choice, MultiChoice, lookup, and person values. It routes the specialized choice and ID fields through the same validation as their focused helpers:

```ts
import { serializeSharePointFieldValue } from "@spfx-fast/sharepoint-ui/sharepoint-fields";

serializeSharePointFieldValue(titleField, "Quarterly access review"); // { Title: "Quarterly access review" }
serializeSharePointFieldValue(approvedField, true);                    // { Approved: true }
serializeSharePointFieldValue(amountField, "125.50");                  // { Amount: 125.5 }
serializeSharePointFieldValue(dueDateField, new Date());               // ISO date string
serializeSharePointFieldValue(linkField, { url: "/sites/ops/guide", description: "Open guide" });
```

The helper rejects text values over SharePoint's `MaxLength` and numeric values outside `MinimumValue`/`MaximumValue` (or `Min`/`Max`) when those bounds are present.

Use `null` to clear nullable values. Read-only fields and empty values for required fields are rejected; `false` and `0` are valid values. Numeric strings are parsed as whole values; non-finite numbers and unsafe integers are rejected, and configured `Decimals` precision is enforced (trailing zeroes do not count as extra precision). URL fields accept absolute HTTP(S) or server-relative URLs and serialize to SharePoint's [`SP.FieldUrlValue`](https://learn.microsoft.com/en-us/dotnet/api/microsoft.sharepoint.client.fieldurlvalue?view=sharepoint-csom) shape. Date-only ISO strings are preserved, date-time strings with a timezone keep that offset, and local date-time strings or `Date` objects become ISO UTC strings. The helper does not send the request or replace SharePoint-side validation.

## Render with existing controls

The recipe uses the same component names and prop concepts used elsewhere in the library. For a URL field, use `urlFormat` to render the saved URL as a `Link` or `Image` in a record view; use the `input` recipe when editing. A choice field can be rendered as a Select without inventing app-specific naming:

```tsx
import { Select } from "@spfx-fast/sharepoint-ui/react";
import { getSharePointFieldAdapter } from "@spfx-fast/sharepoint-ui/sharepoint-fields";

const field = getSharePointFieldAdapter(column);

if (field.hidden || field.control !== "select") return null;

return (
  <Select label={field.label} name={field.name} required={field.required} disabled={field.readOnly}>
    {field.choices?.map(choice => <option key={choice} value={choice}>{choice}</option>)}
  </Select>
);
```

For a SharePoint Note field, pass the original field metadata to `RichTextEditor`; it uses the same rules as `getRichTextEditorFieldOptions()`:

```tsx
import { RichTextEditor } from "@spfx-fast/sharepoint-ui/react";

<RichTextEditor label={field.label} name={field.name} required={field.required} field={column} />
```

The adapter describes the editor and provides helpers for lookup option URLs and field-value payloads. Your app still owns authorized fetching, people search, permissions, persistence, and handling SharePoint's response. Unknown field types remain explicit instead of being coerced to text.
