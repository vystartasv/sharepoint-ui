---
title: Use SharePoint UI in SPFx
description: Add the library to an SPFx 1.24 web part and pass the current SharePoint locale into the provider.
---

## Install

```sh
npm install @vilius/sharepoint-ui
```

The React adapter is optional at package level. In an SPFx React web part, import the provider and only the components that view needs:

```tsx
import { SharePointUIProvider, Button, TextField } from "@vilius/sharepoint-ui/react";

export function RequestForm({ locale }: { locale: string }) {
  return (
    <SharePointUIProvider lang={locale}>
      <form>
        <TextField label="Request title" name="title" required />
        <Button appearance="primary" type="submit">Create request</Button>
      </form>
    </SharePointUIProvider>
  );
}
```

Pass the page culture from the web part rather than hard-coding English:

```tsx
<RequestForm locale={this.context.pageContext.cultureInfo.currentUICultureName} />
```

The provider supplies shared locale, direction, appearance, and theme configuration. The web part remains responsible for SharePoint list access, permissions, save operations, and error recovery; controls expose values and events for that application code.

## Keep components inside the host layout

Render the web part normally inside its section. Components inherit CSS custom properties from their host and use the SharePoint section's theme values. Avoid adding a full-page background or a second application shell unless the web part owns that whole surface.

## Choose imports deliberately

Import components from `@vilius/sharepoint-ui/react` for React composition. Import a leaf definition such as `@vilius/sharepoint-ui/elements/button` for framework-neutral use. The [component catalog](/sharepoint-ui-docs/catalog/) shows the matching tag, slots, callbacks, and styling hooks.
