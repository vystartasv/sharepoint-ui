title: Roadmap
description: What we plan to improve next.
---

## 1. Make the editor work well on phones

Text can be selected and formatted; the toolbar and color controls fit without covering the editor.

## 2. Make the docs work on every screen

Examples are easy to find and use on phones, tablets, and desktops.

## 3. Simplify the project

Remove layers that add cost without a clear user benefit. Keep a layer only when its benefit justifies its measured performance cost.

## 4. Finish the components people need

Use Fluent as a checklist for expected component breadth, not as a design or behavior template. Build each component around the needs and experience we choose for this library.

Done when the components people expect are present, useful, accessible, theme-aware, and fast in real SharePoint work.

## 5. Prepare the next release

Release when the editor and docs work well, comparisons are complete, and performance costs are understood. Vilius will publish the package to npm.

No release dates are set yet.
